# LVGL 9.40 Migration Guide for EEZ Studio Projects

## Overview

LVGL version 9.40 introduced breaking API changes that affect code generated by EEZ Studio. This document explains the changes and how to fix your projects.

## Breaking Changes

### 1. Style Getter Functions - lv_part_t Requirement

**Function Affected:** `lv_obj_get_style_opa()`

**What Changed:**
- **Before (LVGL < 9.40):** Second parameter accepted `int` (e.g., `0`)
- **After (LVGL 9.40+):** Second parameter requires `lv_part_t` enum type

**Error Message:**
```
error: invalid conversion from 'int' to 'lv_part_t' [-fpermissive]
```

### 2. Common Problem Patterns in EEZ Studio Generated Code

#### Pattern 1: Animation Callbacks

**Before (Broken in LVGL 9.40):**
```cpp
static int32_t anim_callback_get_opacity(lv_anim_t * a) { 
    return lv_obj_get_style_opa((lv_obj_t *)a->user_data, 0); 
}
```

**After (Fixed for LVGL 9.40):**
```cpp
static int32_t anim_callback_get_opacity(lv_anim_t * a) { 
    return lv_obj_get_style_opa((lv_obj_t *)a->user_data, LV_PART_MAIN); 
}
```

#### Pattern 2: Style Getter Functions

**Before (Broken in LVGL 9.40):**
```cpp
void objGetStyleOpa(FlowState *flowState, unsigned int componentIndex) {
    lv_obj_t *obj = getLvglObjectFromIndex(componentIndex);
    int32_t opa = (int32_t)lv_obj_get_style_opa(obj, 0);
}
```

**After (Fixed for LVGL 9.40):**
```cpp
void objGetStyleOpa(FlowState *flowState, unsigned int componentIndex) {
    lv_obj_t *obj = getLvglObjectFromIndex(componentIndex);
    int32_t opa = (int32_t)lv_obj_get_style_opa(obj, LV_PART_MAIN);
}
```

## Available lv_part_t Values

When fixing your code, choose the appropriate part type for your use case:

| Constant | Description | Common Use Case |
|----------|-------------|-----------------|
| `LV_PART_MAIN` | Main part of object | Most common, default part |
| `LV_PART_SCROLLBAR` | Scrollbar part | For scrollable objects |
| `LV_PART_INDICATOR` | Indicator part | Sliders, bars, switches |
| `LV_PART_KNOB` | Knob part | Sliders, arc controls |
| `LV_PART_SELECTED` | Selected state | Lists, dropdowns |
| `LV_PART_ITEMS` | Individual items | Lists, dropdowns |
| `LV_PART_CURSOR` | Cursor part | Text areas, inputs |

**For EEZ Studio generated code, `LV_PART_MAIN` is almost always the correct choice.**

## Quick Fix Guide

### Option 1: Automatic Fix (Recommended)

Use the provided Python script:

```bash
# Navigate to your Arduino project directory
cd C:\Users\YourName\Documents\Arduino\YourProject

# Run the fix script (with backup)
python path\to\fix-lvgl940.py --in-place eez-flow.cpp eez-flow.h

# Or without backup
python path\to\fix-lvgl940.py --in-place --no-backup eez-flow.cpp eez-flow.h
```

### Option 2: Manual Fix

1. Open `eez-flow.cpp` in your text editor
2. Find all occurrences of `lv_obj_get_style_opa(`, typically on lines like:
   - Animation callback functions (around line 3837 in your case)
   - Style getter functions (around line 4404 in your case)
3. Replace the second parameter `0` with `LV_PART_MAIN`

Example using Find & Replace:
- **Find:** `lv_obj_get_style_opa(([^,]+), 0)`
- **Replace:** `lv_obj_get_style_opa($1, LV_PART_MAIN)`
- Use regex mode if your editor supports it

### Option 3: IDE Search and Replace

**Arduino IDE:**
1. Edit → Find... (Ctrl+F)
2. Search for: `lv_obj_get_style_opa`
3. Manually review each occurrence and change `, 0)` to `, LV_PART_MAIN)`

**VS Code:**
1. Edit → Replace (Ctrl+H)
2. Enable regex mode (.*)
3. Find: `lv_obj_get_style_opa\(([^,]+),\s*0\)`
4. Replace: `lv_obj_get_style_opa($1, LV_PART_MAIN)`

## Verification

After applying the fix, compile your project:

```bash
# Arduino IDE: Click Verify button
# PlatformIO: 
pio run
```

You should no longer see the error:
```
error: invalid conversion from 'int' to 'lv_part_t' [-fpermissive]
```

## Future Prevention

### For New Projects

After generating code with EEZ Studio:
1. Always run the fix script before compiling
2. Consider adding the fix script to your build process

### Integration with Build Systems

**PlatformIO Example:**

Create `fix_eez_code.py` in your project root:
```python
Import("env")
import subprocess
import os

# Path to the fix script
fix_script = os.path.join("tools", "eez-studio", "fix-lvgl940.py")

# Run fix before building
def fix_eez_code(source, target, env):
    print("Fixing EEZ Studio code for LVGL 9.40...")
    subprocess.run([
        "python", fix_script,
        "--in-place", "--no-backup",
        "src/eez-flow.cpp",
        "src/eez-flow.h"
    ])

env.AddPreAction("buildprog", fix_eez_code)
```

Add to `platformio.ini`:
```ini
[env:esp32]
platform = espressif32
board = esp32dev
framework = arduino
extra_scripts = pre:fix_eez_code.py
```

## Troubleshooting

### Still Getting Errors?

1. **Check LVGL Version:**
   ```cpp
   // In your main file
   #include "lvgl.h"
   Serial.println(LVGL_VERSION_INFO);
   ```

2. **Verify All Files Were Fixed:**
   Search for remaining instances:
   ```bash
   grep -n "lv_obj_get_style_opa.*,\s*0\s*)" *.cpp *.h
   ```

3. **Clean Build:**
   Sometimes cached files cause issues:
   - Arduino IDE: Delete build folder
   - PlatformIO: `pio run --target clean`

### Common Mistakes

❌ **Wrong:** `lv_obj_get_style_opa(obj, NULL)`
✅ **Correct:** `lv_obj_get_style_opa(obj, LV_PART_MAIN)`

❌ **Wrong:** `lv_obj_get_style_opa(obj, 0x00)`
✅ **Correct:** `lv_obj_get_style_opa(obj, LV_PART_MAIN)`
